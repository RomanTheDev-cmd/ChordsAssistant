# Журнал работы над Harmonic Shadow

Назначение: передать AI-агентам ход обсуждения, причины ключевых решений и историю реализации.  
Текущий статус функций см. в [STATUS.md](STATUS.md), правила продолжения — в [AGENTS.md](AGENTS.md), пользовательский сценарий — в [README.md](README.md). Журнал хранит историю и не заменяет актуальный статус.

## Хронология обсуждения и решений

Точные временные метки сообщений чата не сохранены, поэтому ниже решения перечислены в порядке обсуждения. Даты коммитов приведены отдельно по истории GitHub.

### 1. Исходная цель

Пользователь описал локальный macOS-инструмент Harmonic Shadow для электронной, атмосферной, индустриальной и кинематографической музыки. Основной сценарий — анализ уже существующего музыкального материала на протяжении нескольких тактов и предложение нескольких музыкально связанных гармонических вариантов.

В исходные требования вошли анализ аккордов, тональных центров, функций, баса, ритма, голосоведения, повторов, заимствований и модуляций; режимы Dark, Melancholic, Tension, Horror, Epic, Mystery, Release и Custom; затемнение отдельных участков, минимум пять вариантов, оценка музыкальной связности, MIDI, Logic Pro, локальная работа и автоматические тесты.

### 2. Уточнение приоритета генерации

Пользователь уточнил: генерация с нуля по выбранной тональности допустима, но вторична. Приоритет — взять текущие MIDI-данные пользователя, проанализировать гармонию и предложить вставки, которые можно применить в Logic.

Зафиксировано: не строить основной пользовательский сценарий вокруг случайной генерации аккордов, ручного ввода прогрессии или отдельной программы для создания материала с нуля.

### 3. Реалистичная интеграция с Logic Pro

Обсудили, куда можно поставить плагин и как получить материал нескольких дорожек. Стандартный Logic AU MIDI FX получает проходящие через свой экземпляр MIDI-события дорожки во время проигрывания; он не сканирует остановленные/записанные MIDI-регионы и не собирает весь проект с аудиомастера.

Поэтому выбрана схема: MIDI FX-экземпляр на каждой нужной MIDI-дорожке, один проход воспроизведения для захвата, общая сессия экземпляров, общий просмотр и выбор одной партии или всех захваченных партий. Не заявлять чтение регионов, анализ мастер-канала или доступ к дорожке без экземпляра эффекта.

### 4. Одно окно для всех дорожек и целевые подсказки

Пользователь хотел собирать данные со всех нужных дорожек в одном окне и получать подсказки отдельно для каждой партии. Выбран общий координатор захвата между экземплярами. Окно любого экземпляра показывает общий материал; пользователь выбирает партию либо все партии для генерации.

Названия партий вводятся вручную: стандартный AU MIDI FX не предоставляет надёжного доступа к именам дорожек Logic.

### 5. Вставка без неудобного экспорта

Пользователь отверг сценарий «экспортировать весь MIDI и затем вручную импортировать». Требуемый жест — перетащить отдельную подсказку из окна плагина в проект Logic.

Реализован UI drag-and-drop строки варианта через временный MIDI Type 1-файл и системную передачу файла. Для пользователя нет диалога экспорта и не нужно искать файл. Внутри механизм использует временный файл; фактическая совместимость перетаскивания с Arrangement Logic пока не подтверждена в установленном host.

### 6. Horror и контроль эмоциональной дуги

Пользователь отдельно попросил режим Horror с самыми мрачными последовательностями. Добавлен `Mood::Horror`; движок задаёт ему более высокий целевой уровень напряжения, чем, например, Release. Проверка тестами движка включает сравнение Horror и Release.

### 7. Сохранение состояния и продолжение разработки

Пользователь попросил сохранить выполненную работу в Git и остановиться; затем дал команду продолжить. Работа продолжилась в приватном репозитории. 12 октября пользователь запросил инструкцию для следующих AI-агентов; добавлен [AGENTS.md](AGENTS.md) с архитектурой, проверенным состоянием, ограничениями и порядком продолжения.

## Что сделано в текущей версии

- JUCE AUv2 MIDI FX на C++17, ориентированный на Logic Pro/macOS и Apple Silicon.
- Захват проходящего MIDI с нескольких экземпляров, отдельные партии и общий piano roll.
- Анализ ладового/тонального центра и аккордовых событий, распознавание басовых обращений и ручные коррекции аккордов.
- Пять детерминированных стратегий гармонического развития: Modal Shadow, Chromatic Mediants, Tension Architecture, Common Tone Drift, Pedal & Return.
- Восемь режимов эмоции, в том числе Horror; Darkness, Transformation, кривая напряжения, диапазон и плотность.
- Контроль общих тонов, гармонического ритма и сохранения ритма баса.
- Вторичный режим генерации по выбранной тональности.
- Ранжирование вариантов по голосоведению, связности, трансформации и напряжению.
- Генерация MIDI Type 1 и перетаскивание варианта через временный файл.
- Сохранение общей сессии, пользовательских настроек и ручных правок аккордов в состоянии AU.

Подробные границы проверенного и непроверенного состояния перечислены в [AGENTS.md](AGENTS.md) и [STATUS.md](STATUS.md).

## Проверки и незакрытые проблемы

- Тесты движка проверяют простую C-мажорную прогрессию, Dorian, хроматическую гармонию, партии баса и аккордов, обращение C/E, пять вариантов, Horror против Release, MIDI Type 1 и восстановление состояния.
- GitHub Actions run [38079021119](https://github.com/RomanTheDev-cmd/ChordsAssistant/actions/runs/38079021119) прошёл успешно на commit `9a28554613dc51f114a4ace7da37ed19c8a9fbb8`: macOS 14 собрала arm64 AU, ad-hoc подпись и загрузка artifact `Harmonic-Shadow-AU-arm64` завершились успешно.
- Успешная сборка не означает, что плагин уже проверен в Logic. Остаются AU Validation, захват и синхронизация нескольких дорожек в host, повторное открытие проекта, drag-and-drop в Arrangement и общее поведение окна.
- Встроенного MIDI-прослушивания пока нет; используется инструмент Logic после вставки варианта.
- Импорта MIDI Type 0/1 в самостоятельное окно нет. Текущий продуктовый путь — проигрываемый захват через экземпляры MIDI FX.
- Темп-карта с изменениями по тактам не сохраняется; используются текущие захваченные темп и размер.
- Artifact подписывается ad-hoc; Developer ID и notarization не настроены.

Сборка ранее выявляла ошибки JUCE/CMake: отсутствие языка C в CMake проекте, неоднозначные преобразования `juce::String` у AppleClang, отсутствующую фабрику `createPluginFilter()` и не объявленные поля диапазона нот в редакторе. Они были исправлены до успешного macOS workflow; не откатывать эти исправления.

5. После изменений обновлять статус и журнал, сохраняя продуктовый приоритет: анализ текущего материала и быстрые drag-and-drop MIDI-вставки, без облака и языковых моделей.
