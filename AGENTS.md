## Цель продукта и зафиксированная архитектура

Главная задача — анализировать уже существующую гармонию из проекта Logic Pro и предлагать связанные MIDI-вставки для выбранной партии. Генерация из заданной тональности — вторичный режим.

Приложение сделано как локальный AUv2 MIDI FX для Logic Pro: музыкальный движок на C++17, оболочка и UI на JUCE. Сеть и языковые модели во время работы не используются. JUCE скачивается из публичного репозитория при сборке.

Logic MIDI FX видит поток MIDI своей дорожки во время воспроизведения. Он не читает остановленные или записанные регионы проекта и не получает общий MIDI-поток с аудиомастера. Поэтому текущий сценарий сбора нескольких партий такой:

- поставить экземпляр плагина в MIDI FX-слот перед инструментом на каждой нужной MIDI-дорожке;
- включить захват и проиграть фрагмент;
- экземпляры объединяют ноты в общей сессии по позиции PPQ хоста;
- открыть окно любого экземпляра, выбрать партию или все захваченные партии и получить подсказки.

Не обещайте чтение регионов, анализ с мастера или доступ к дорожкам без активного экземпляра. Названия партий пользователь задаёт вручную.

Вариант перетаскивается из строки подсказки. Реализация создаёт временный MIDI Type 1 и передаёт его через системный файловый drag-and-drop. Это не экспортный диалог, но перенос в Arrangement пока требует проверки в реальной Logic Pro.

Не меняйте основной сценарий на standalone-приложение с обязательным ручным импортом/экспортом без прямого запроса пользователя. Не представляйте вторичный режим генерации из тональности как основную функцию.

## Текущее состояние

### Реализовано в коде

- AUv2 MIDI FX и окно с общим piano roll для захваченных партий.
- Захват MIDI-событий нескольких экземпляров, синхронизация по PPQ позиции и ручные названия партий.
- Оценка тонального центра/лада, распознавание аккордовых событий, функций и басовых обращений; ручная коррекция аккордов.
- Пять детерминированных стратегий: Modal Shadow, Chromatic Mediants, Tension Architecture, Common Tone Drift, Pedal & Return.
- Режимы Dark, Melancholic, Tension, Horror, Epic, Mystery, Release и Custom.
- Darkness, Transformation, кривая напряжения, диапазон и плотность; общий тон, гармонический ритм и ритм баса.
- Вторичный режим генерации от выбранной тональности.
- Ранжирование вариантов по голосоведению, гармонической связности, степени трансформации и соответствию кривой напряжения.
- Вывод MIDI Type 1 с темпом/размером и предложенной партией; drag-and-drop через временный файл.
- Сериализация общего захвата, настроек и ручных коррекций в состояние AU.
- Скрипт сборки и установки arm64 AU: `scripts/install-macos.sh`.

### Что проверено

- `HarmonicEngineExamples` собирается и проходит CTest в Linux. Тестовые примеры и точные границы см. в [STATUS.md](STATUS.md).
- GitHub Actions run [38079021119](https://github.com/RomanTheDev-cmd/ChordsAssistant/actions/runs/38079021119) завершился успешно для commit `9a28554613dc51f114a4ace7da37ed19c8a9fbb8`: arm64 AU собран на macOS 14, ad-hoc подписан и загружен artifact `Harmonic-Shadow-AU-arm64`.
- CI подтверждает сборку и упаковку, но не прохождение AU Validation и не работу внутри Logic Pro.

### Не реализовано или не подтверждено

- Нет импорта MIDI-файлов Type 0/Type 1 в отдельное окно приложения. Текущий путь — захват проигрываемого MIDI через MIDI FX на каждой нужной дорожке.
- Нет встроенного прослушивания вариантов; вариант можно перетащить на MIDI-регион и использовать инструмент Logic.
- Не сохраняется автоматизация карты темпа по тактам; используются текущие темп и размер.
- В реальной Logic Pro ещё не проверены AU Validation, захват и PPQ-синхронизация нескольких партий, сохранение/повторное открытие проекта, перетаскивание MIDI в Arrangement и работа окна.
- Drag-and-drop реализован в UI, но его совместимость с Logic не подтверждена host-проверкой.
- CI подписывает artifact ad-hoc; Developer ID подпись и notarization не настроены.

## Проблемы и причины

1. **Плагин не читает весь проект.** Это ограничение стандартного AU MIDI FX: экземпляр получает поток событий своей дорожки, а не список MIDI-регионов Logic. Для нескольких партий нужны экземпляры на нужных дорожках и проигрывание фрагмента.
2. **Сборка не равна host-проверке.** Текущая среда разработки — Linux; macOS CI компилирует и подписывает AU, но не запускает Logic.
3. **Перетаскивание не подтверждено.** Вариант передаётся внешним файловым drag-and-drop из окна AU с помощью временного `.mid`; нужно проверить фактическую вставку в Arrangement.
4. **CI artifact не релизный пакет.** Ad-hoc подпись годится для локальной проверки; распространение вне этого сценария потребует Developer ID подписи и notarization.
5. **Исправленные ошибки сборки:** CMake проекту был нужен язык C для JUCE; AppleClang требовал явные преобразования `juce::String`; требовалась фабрика `createPluginFilter()`; поля диапазона нот должны быть объявлены в редакторе. Не откатывайте эти исправления.

## Рабочие правила

- Гармония должна развиваться из исходной фразы музыкально осмысленно, а не случайной перестановкой аккордов.
- Не заявляйте, что Logic протестирован, пока этого не было в установленном host.
- Не обещайте чтение регионов, анализ мастер-канала или дорожек без MIDI FX.
- Сохраняйте полностью локальную работу без облачных API и музыкальной генерации языковыми моделями.
- Сохраняйте совместимость сериализованного состояния проекта либо явно обрабатывайте его предыдущую версию.
