## Цель продукта и зафиксированная архитектура

Главная задача — анализировать уже существующую гармонию из проекта Logic Pro и предлагать связанные MIDI-вставки для выбранной партии. Генерация из заданной тональности — вторичный режим.

Приложение сделано как локальный AUv2 MIDI FX для Logic Pro: музыкальный движок на C++17, оболочка и UI на JUCE. Сеть и языковые модели во время работы не используются. JUCE скачивается из публичного репозитория при сборке.

Logic MIDI FX видит поток MIDI своей дорожки во время воспроизведения. Он не читает остановленные или записанные регионы проекта и не получает общий MIDI-поток с аудиомастера. Поэтому текущий сценарий сбора нескольких партий такой:

- поставить экземпляр плагина в MIDI FX-слот перед инструментом на каждой нужной MIDI-дорожке;
- включить захват и проиграть фрагмент;
- экземпляры объединяют ноты в общей сессии по позиции PPQ хоста;
- открыть окно любого экземпляра, выбрать партию или все захваченные партии и получить подсказки.

Не обещайте чтение регионов, анализ с мастера или доступ к дорожкам без активного экземпляра. Названия партий пользователь задаёт вручную.

Вариант перетаскивается из строки подсказки. Реализация создаёт временный MIDI Type 1 и передаёт его через системный файловый drag-and-drop. Это не экспортный диалог, но перенос в Arrangement пока требует проверки в реальной Logic Pro.

Не меняйте основной сценарий на standalone-приложение с обязательным ручным импортом/экспортом без прямого запроса пользователя. Не представляйте вторичный режим генерации из тональности как основную функцию.

## Текущее состояние

### Реализовано в коде

- AUv2 MIDI FX и окно с общим piano roll для захваченных партий.
- Захват MIDI-событий нескольких экземпляров, синхронизация по PPQ позиции и ручные названия партий.
- Оценка тонального центра/лада, распознавание аккордовых событий, функций и басовых обращений; ручная коррекция аккордов.
- Пять детерминированных стратегий: Modal Shadow, Chromatic Mediants, Tension Architecture, Common Tone Drift, Pedal & Return.
- Режимы Dark, Melancholic, Tension, Horror, Epic, Mystery, Release и Custom; параметры Darkness, Transformation, кривая напряжения, диапазон и плотность.
- Контроль общего тона, гармонического ритма и сохранения ритма атак/длительностей баса.
- Вторичный режим Generate from key.
- Ранжирование вариантов по голосоведению, гармонической связности, степени трансформации и соответствию кривой напряжения.
- MIDI Type 1 для варианта с метаданными темпа/размера и нотой/партией.
- Сохранение захваченной сессии, меток, параметров и ручных коррекций в состоянии плагина Logic.
- Скрипт сборки/установки Apple Silicon: `scripts/install-macos.sh`.

### Что проверено

- Примеры гармонического движка и MIDI-файла проверяются тестом `HarmonicEngineExamples`: тональная C-мажорная последовательность, Dorian, хроматическая гармония, отдельные басовая и аккордовая партии, обращение C/E, пять вариантов, Horror против Release, ритм баса, MIDI Type 1 и восстановление общей сессии.
- GitHub Actions run [38079021119](https://github.com/RomanTheDev-cmd/ChordsAssistant/actions/runs/38079021119) завершился успешно для commit `9a28554613dc51f114a4ace7da37ed19c8a9fbb8`: CMake собрал arm64 AU на macOS 14, ad-hoc подпись прошла, artifact `Harmonic-Shadow-AU-arm64` загружен.
- Эта CI-проверка доказывает сборку и упаковку артефакта. Она **не** доказывает прохождение AU Validation или работу плагина внутри Logic.

### Не реализовано или не подтверждено

- Нет импорта MIDI-файлов Type 0/Type 1 в отдельное окно приложения. Текущий путь — захват проигрываемого MIDI через MIDI FX на каждой нужной дорожке.
- Нет встроенного прослушивания вариантов через синтезатор. Для прослушивания перенесите вариант на MIDI-регион и используйте инструмент Logic.
- Не сохраняется автоматизация карты темпа по тактам; используется последний захваченный темп и размер.
- Не проверены в установленной Logic Pro: AU Validation, захват нескольких партий и PPQ-синхронизация, сохранение/повторное открытие проекта, внешний drag-and-drop MIDI в Arrangement и поведение окна.
- Drag-and-drop уже реализован в UI, но его совместимость с реальным окном Logic и целевым местом вставки неизвестна до host-проверки.
- Нет релизной Developer ID подписи и notarization; CI artifact подписывается ad-hoc для локальной проверки.

## Проблемы и их причины

1. **Плагин не может прочитать весь проект сам по себе.** Это ограничение стандартного AU MIDI FX: он получает MIDI-события, проходящие через экземпляр, а не список записанных регионов Logic. Обходной сценарий — поставить плагин на нужные дорожки и воспроизвести фрагмент. Не имитируйте доступ к остановленным регионам.
2. **Среда разработки не является Logic Pro.** Проверки Linux подтверждают движок, а macOS CI — компиляцию и ad-hoc подпись. Ни одно из них не заменяет запуск в Logic на macOS.
3. **Неизвестна надёжность передачи MIDI перетаскиванием.** Используется системный drag файлов из окна плагина через временный `.mid`; нужен практический тест в Arrangement. Если Logic не принимает payload, исследуйте API drag-and-drop/поведение AU окна, не называйте функцию проверенной.
4. **Установка из CI пока не равна релизному распространению.** Артефакт рассчитан на ручную установку и локальную проверку; распространение вне этого сценария потребует Developer ID подписи и notarization.
5. **История ошибок сборки CI (уже исправлены; не откатывать исправления):** CMake требовал язык C для JUCE; AppleClang обнаружил неоднозначные преобразования `juce::String`; требовалась фабрика `createPluginFilter()`; поля диапазона `lowPitch_` и `highPitch_` отсутствовали в объявлении редактора. Эти проблемы исправлены в текущем успешном arm64 workflow.

## Рекомендуемый порядок дальнейшей работы

1. В первую очередь получить и установить artifact `Harmonic-Shadow-AU-arm64`, пересканировать Audio Units и пройти host-проверки из раздела выше.
2. Если тест в Logic выявит проблему, исправлять её по наблюдаемому поведению и сохранять точные шаги воспроизведения.
3. При изменениях гармонического движка добавлять детерминированные примеры в `Tests/HarmonicEngineTests.cpp` и выполнять тесты:
   ```sh
   cmake -S . -B build -DHARMONIC_SHADOW_BUILD_TESTS=ON -DHARMONIC_SHADOW_BUILD_PLUGIN=OFF
   cmake --build build --parallel
   ctest --test-dir build --output-on-failure
   ```
4. Для изменений AU/UI запускать macOS workflow и отдельно проверять фактическое поведение в Logic, если затронуты host-взаимодействие, транспорт, состояние или drag-and-drop.
5. После заметного изменения обновлять `STATUS.md`, README при пользовательских изменениях и эту инструкцию при изменении архитектуры/приоритетов.

## Правила для следующих агентов

- Сохраняйте работу от уже существующей музыкальной фразы; случайная перестановка аккордов не удовлетворяет цели.
- Для новых гармонических приёмов объясняйте музыкальный эффект в контексте выбранного режима и добавляйте проверяемые примеры.
- Не утверждайте, что Logic протестирован, пока не выполнен тест в установленном host; отдельно указывайте, что именно проверено.
- Не скрывайте ограничения AU MIDI FX и не обещайте чтение регионов или мастер-канала.
- Не добавляйте облачные API или генерацию музыки языковыми моделями: приложение должно оставаться локальным.
- Сохраняйте совместимость сериализованного состояния проекта либо явно обрабатывайте старую версию состояния.
